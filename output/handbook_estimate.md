## 1. Token count

**The handbook is 10,058 tokens.**

**How we got it:** we ran the whole file through OpenAI's open-source tokenizer library [`tiktoken`](https://github.com/openai/tiktoken) with the `o200k_base` encoding, the one the GPT-4o and GPT-5-family models use, and counted the tokens:

```python
import tiktoken
enc = tiktoken.get_encoding("o200k_base")
len(enc.encode(open("data/shop_handbook.md").read()))   # -> 10,058
```

OpenAI hasn't published gpt-6-luna's exact tokenizer, so we treat this as a close estimate. The API also adds a handful of tokens of message framing per call. Problem 4 replaces the estimate with the `input_tokens` the API reports.

## 3. What the handbook alone costs

Input tokens only, for N = 10,058 handbook tokens. Output, the vendor document, and the system-prompt wording are left out on purpose; this is the fixed cost the handbook adds to every call.

### One call

| Case | Math | Cost |
|---|---|---:|
| Without caching | 10,058 × $0.10 / 1,000,000 | **$0.0010058** |
| With caching, first call (cache write) | 10,058 × $0.125 / 1,000,000 | **$0.0012572** |
| With caching, later call (cache read) | 10,058 × $0.01 / 1,000,000 | **$0.0001006** |

A single call is about a tenth of a cent. The first cached call costs **25% more** than an uncached one (it pays to store the prefix). Every call after that is **90% cheaper**.

### 1,000 calls

| Case | Math | Cost | vs no cache |
|---|---|---:|---:|
| Without caching | 1,000 × 10,058 × $0.10/1M | **$1.0058** | — |
| With caching, best case (1 write + 999 reads, all within the cache's lifetime) | $0.0012572 + 999 × $0.0001006 | **$0.1017** | -89.9% |
| With caching, spread over an 8-hour day (30-min TTL → 16 writes + 984 reads) | 16 × $0.0012572 + 984 × $0.0001006 | **$0.1191** | -88.2% |
| With caching, worst case (the cache always expires before the next call → 1,000 writes) | 1,000 × $0.0012572 | **$1.2572** | +25.0% |

Caching cuts the handbook bill for 1K calls from about **$1.01 to about $0.10**, a 90% saving, as long as the calls come close enough together to reuse the cache. If calls are hours apart, every call pays the write premium and caching costs more than not caching.

## 4. Assumptions to check in Problem 4

1. **Token count.** Real `input_tokens` should be about 10,058 plus the system prompt, the vendor document, and message framing. The API, not tiktoken, has the final word on gpt-6-luna.
2. **Cache hits.** On the second and later calls, `input_tokens_details.cached_tokens` should be close to the handbook size, provided the handbook sits **first** in the prompt, unchanged byte-for-byte, with a `prompt_cache_breakpoint` right after it (Lecture 11). Providers may cache in fixed-size blocks, so a few dozen tokens at the end may still bill as normal input.
3. **Cache write.** The first call should show about the same number in `cache_write_tokens`, billed at $0.125/1M.
4. **Billing math.** `input_tokens` already includes the cached and cache-write tokens, so the uncached part = input − cached − cache_write, billed at $0.10/1M.
